Third-Party OAuth: Already Signed In

Which interaction should Keycast use when the browser already has a session cookie and the user starts OAuth for a new app?

A. Consent First, Account Callout Inline
Signed in as
alice@example.com
This app will connect to this account.
Use a different account
Existing consent card below

Inline Banner

Minimal change. Keep the consent page, but make the active account obvious and add a switch-account link at the top.

B. Account Chooser, Then Consent
Continue as
alice@example.com
Selected
Use a different account
Sign in with another email or create one
Consent screen appears after selection

Chooser Then Consent

Google-style. First choose the account explicitly, then show permissions for the selected account.

C. Combined Account + Consent
Connecting as
alice@example.com
Permissions list for this app
Continue
Switch account

Combined Screen

Fastest path. Show the chosen account and permissions on one screen with a secondary switch-account action.

What I’m leaning toward

  • B if we want the account choice to feel explicit and Google-like.
  • C if we want fewer steps while still making the account unmistakable.

Tradeoff to watch

  • A is easiest to ship, but it still risks users skimming past the account identity.
